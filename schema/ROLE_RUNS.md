# Role-run evaluation schema v1

This is an additive experiment layer. It does not change the meaning of
`data/runs/` or `data/scoreboard.jsonl`.

## Layout

```text
data/role-runs/{run_id}/
  manifest.json
  events.jsonl
```

## Design rules

1. `events.jsonl` is append-only raw task evidence.
2. Derived metrics and recommendations are generated by scripts.
3. Missing usage or cost values are `null`, never guessed.
4. API keys, authorization headers, and sensitive source content must not be recorded.
5. A recommendation never changes a role by itself while policy mode is `shadow`.

## Adapter contracts

The core does not depend on Codex, a specific model provider, or JSONL. Adapters expose three
small contracts:

- `AgentAdapter`: `name`, `run(input)`
- `ModelCatalogProvider`: `name`, `listModels()`
- `TaskEvaluator`: `name`, `evaluate(run)`

The Codex adapter and JSONL store are the first implementations. A new Agent or
provider should implement an adapter instead of adding provider-specific logic
to `src/core/`.

Recommendations expose a `pareto_frontier`: eligible models that are not
dominated across quality, success rate, cost, P95 latency, regression, and
rework. The default recommendation remains conservative and does not mutate
role configuration in `shadow` mode.

Model identity is the pair `(provider, model)`. Catalogs, price snapshots,
statistics, baselines, Pareto frontiers, recommendations, and promotion gates
are isolated by provider. Events with `provider = "unknown"` can be displayed
for audit purposes but cannot participate in provider promotion decisions.
Historical events with the former provider ID `ccsub` are canonicalized to
`sub2api` so existing evidence remains available after the rename.

## Recorded command adapter

`node scripts/codex-run.mjs` is an opt-in wrapper for a Codex-compatible
command. It records process status and wall time automatically. Objective
acceptance results and usage/cost fields must be appended after the command
finishes; the wrapper never infers quality from an exit code.

## Objective evaluation adapter

`node scripts/evaluate-run.mjs` runs a command specification and appends an
`evaluation_finished` event. Commands are passed as JSON arrays so the
evaluator does not invoke a shell:

```bash
ROLEBENCH_ROOT=/path/to/0genlab node scripts/evaluate-run.mjs \
  --run-id "$RUN_ID" \
  --project /workspace/project \
  --test-command '["npm","test"]' \
  --regression-command '["python3","regression_test.py"]'
```

The adapter records exit status, test counts when they can be parsed, a
regression result, `git diff --check`, and a compact diff stat. It does not
store stdout/stderr and does not infer `quality_score` from a process exit
code.

## Passive Codex session ingestion

`node scripts/ingest-codex-sessions.mjs` reads Codex's local session JSONL and
records only metadata, role/model identity, elapsed time, Token usage, and
calculated cost. User prompts, model responses, tool output, and source code
are not copied into `data/role-runs/`.

It is idempotent by Codex session ID:

```bash
ROLEBENCH_ROOT=/path/to/0genlab node scripts/ingest-codex-sessions.mjs
```

If the parser or price snapshot changes, pass `--refresh` to rebuild existing
session-derived runs instead of appending duplicate events.

Usage and cost are only recorded when supplied by the Agent or explicitly
priced by the caller. `codex-run.mjs` accepts `--usage-file`,
`--input-price-per-million`, and `--output-price-per-million`; without a
trusted usage source or both explicit prices, `cost_usd` remains `null`.

Run `node scripts/sync-provider-catalogs.mjs` followed by
`node scripts/validate-provider-models.mjs` to verify every provider-specific
default and candidate. Run `node scripts/sync-model-prices.mjs --provider
<provider>` to generate a provider-specific price snapshot. A snapshot is a
derived cache and includes its source and fetch time; it is never treated as a
historical replacement for the raw usage evidence.

The objective evaluator also calculates an explainable `quality_score` from
tests, regression, diff cleanliness, rework, and optional human acceptance.
Missing evidence is excluded from the weighted average and reported through
`quality_confidence`; missing evidence is never treated as success.

## Evaluation boundary

The core evaluator uses objective evidence: pristine tests, E2E results, diff
checks, regression checks, wall time, token usage, cost, retries, rework, and
human acceptance. An LLM judge may be added as a separate experiment for
subjective roles such as research or planning, but its score must not enter the
default promotion gate unless it has been calibrated against human labels.
